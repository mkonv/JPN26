# Развёртывание на GitHub Pages

## Важно о приватности
Обычный GitHub Pages следует считать **публичным сайтом**. В проекте выставлен `noindex/nofollow`, чтобы не поощрять индексацию поисковиками, но это не пароль, не авторизация и не ограничение доступа. Не публикуйте в исходниках секреты, паспортные данные или коды бронирований.

Коды бронирований/verification numbers, которые вводятся через интерфейс «Карман», живут только в памяти текущей вкладки. Они не записываются в `localStorage`/`sessionStorage` и исчезают после перезагрузки страницы.

## Публикация
1. Загрузите **содержимое** этой папки в корень репозитория.
2. Откройте `Settings → Pages` и выберите `Source: GitHub Actions`.
3. Отправьте изменения в `main` или вручную запустите `Deploy Japan 2026 to GitHub Pages` на вкладке `Actions`.
4. Workflow проверит зависимости, код, внутренние ссылки/assets, regression-тесты, offline/PWA и mobile layout, затем опубликует свежесобранный каталог `out/`.

Поддерживается project-site адрес вида `https://USERNAME.github.io/REPOSITORY/`: путь репозитория автоматически передаётся из `actions/configure-pages` через `NEXT_PUBLIC_BASE_PATH`.

После **зелёного** workflow откройте опубликованный PWA на iPhone, нажмите «Проверить и обновить копию» и выполните холодный запуск в авиарежиме. Именно зелёный GitHub Actions run является финальным production gate.

## Что намеренно не лежит в архиве исходников
`out/`, `.next/`, `node_modules/` и generated `/output/` не включаются. Это исключает публикацию устаревшего статического export; workflow всегда строит сайт заново из канонических исходников.
